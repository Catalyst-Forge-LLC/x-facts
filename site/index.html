Structure, evidence, and enforcement

Keep these four readings apart. Mixing them turns a useful label into a fake certificate.

  • Schema-valid structure The file matches the published schema and closed enums. A passing validator proves only that.
  • Source-backed claims A named document, repository, or publisher field supports the value. Cite it, or mark the field undisclosed.
  • Observed behavior Someone checked a specific implementation, version, or controlled run. One example is not a universal guarantee.
  • Enforced restrictions A host or runtime actually prevents the action. Configured intent is not the same as enforced policy.

Factual declarations and assessments stay distinct. A context window is a declaration. ModelFacts qualitative ratings such as high or medium are assessments. They are not objective measurements unless a method and source are attached.

Where a machine-readable source exists, our generators extract the value directly: package manifests for AppFacts, model config and metadata for ModelFacts, a server's recorded tools/list for the Panel. Declarations a person writes name their sources and stay separate from extracted values. Child label sites own their authoritative rows. This hub does not overwrite them.

Shared rules

Every label in the family keeps the same skeleton.

  • Do not guess Marketing language stays in READMEs. Missing evidence stays undisclosed or absent.
  • undisclosed over omission When a fact is not disclosed, the file says so. That records absence, not intent. A column of undisclosed still tells you what you cannot compare.
  • Closed enums Comparison fields use fixed vocabularies so two products can sit side by side.
  • CC0 specs, MIT tooling Specs and schemas are public domain. Generators and validators are MIT.

Version and review provenance

A label is useful only when you can tell what it describes, and when.

Use the fields that already exist. Identity usually lives in name, version or package version, repository, and generated.date. AppFacts also has generated.inputs_fingerprint for a stale-input check. SkillFacts has provenance.source and bundled_artifacts. The Panel contract adds subject_identity and a content digest for derived tool surfaces.

Unknown evidence stays unknown. Do not fill a gap with a guessed date or a silent none. Proposed additions, including a shared review-status field, an AppFacts application version, and a SkillFacts package digest, are documented in specs/PROVENANCE.md and are not runtime features until a compatible schema review lands.

Design rationale

How a label earns a domain. Saying no in public is part of the brand.

  1. Someone adopts or installs the thing and needs to trust it at that moment.
  2. The essential facts can be structured, compared, and at least partly derived from source material.
  3. No incumbent format already answers the question well.
